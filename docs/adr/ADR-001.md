# ADR-001: Выбор протокола gRPC (HTTP/2 + Protocol Buffers) для интеграции с сервером СКУД

* **Статус:** Принято (Approved)
* **Дата:** 13.11.2026

## Контекст
На входах в учебные корпуса кампуса перед началом занятий возникает пиковая нагрузка на турникеты (до 200–300 проходов в минуту на одну точку). Классический REST API поверх HTTP/1.1 с передачей текстового JSON создает избыточную задержку на парсинг данных и требует регулярного опроса (polling) для обновления списков пропусков.

## Решение
Выбрать **gRPC** (работающий поверх HTTP/2 с бинарной сериализацией **Protocol Buffers**) в качестве основного транспортного протокола для интеграции модуля `SmartCampus.Infrastructure` с сервером СКУД:
1. Описать контракты передачи данных в строго типизированных `.proto`-файлах.
2. Использовать режим **Server Streaming** для мгновенной отправки событий блокировки утерянного пропуска на турникеты в реальном времени.

## Последствия
### Положительные:
* Снижение объема передаваемого сетевого трафика более чем на 60% по сравнению с JSON.
* Минимальная задержка при проверке мобильного пропуска на турникете (менее 15 мс).
* Строгая типизация контрактов исключает ошибки несовместимости типов данных.

### Отрицательные:
* Бинарный трафик сложнее отлаживать без специальных утилит (`gRPCurl`, Wireshark с декодером).
* Команде требуется время на изучение синтаксиса `.proto`-схем и настройку кодогенерации в .NET.
